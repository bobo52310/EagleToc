Smart TOC Unpin 功能測試

🎯 測試目標

驗證 unpin 功能能夠正確取消已排程的自動顯示，防止用戶移除白名單後 TOC 仍然自動出現。

🔧 修復內容：添加了 timeout 管理機制，確保 unpin 時能夠取消待處理的自動顯示。

🧪 測試步驟

  1. 準備階段：
    • 確保當前網域不在白名單中
    • 重新載入頁面（應該不會自動顯示）
  2. Pin 測試：
    • 手動開啟 Smart TOC
    • 點擊 📌 按鈕加入白名單
    • 確認看到「已將 xxx 加入白名單」通知
  3. 立即 Unpin 測試：
    • 不要關閉 TOC
    • 立即再次點擊 📌 按鈕（現在應該是移除）
    • 確認看到「已從白名單移除 xxx」通知
  4. 關鍵測試：
    • 關閉 TOC 面板
    • 重新載入頁面
    • 觀察：TOC 應該 不會 自動顯示
  5. 確認 Console 日誌：
    • 查看是否有 🗑️ Cancelled pending auto show
    • 確認沒有 ⏰ Scheduling auto show

✅ 成功標準

  • 即時取消：unpin 時立即取消任何待處理的自動顯示
  • 狀態同步：按鈕狀態正確反映白名單狀態
  • 持久效果：重新載入頁面後不會自動顯示
  • 日誌清晰：Console 顯示清楚的取消訊息

🔍 調試信息

如果 unpin 後仍然自動顯示，請檢查以下 Console 日誌：

  • 🔄 Rechecking auto show conditions - 重新檢查條件
  • 🗑️ Cancelled pending auto show - 成功取消自動顯示
  • ⚙️ Should auto show after recheck - 重新檢查結果

預期的 Console 流程：

// Pin 時 🎯 Toggle pin - Current domain: example.com ✅ addToWhitelist: Successfully added and saved 🔄 Rechecking auto show conditions after settings change... // Unpin 時 🎯 Toggle pin - Current domain: example.com ✅ removeFromWhitelist: Successfully removed and saved 🔄 Rechecking auto show conditions after settings change... 🗑️ Cancelled pending auto show due to settings change

⚠️ 重要說明

關鍵測試點：必須在 同一個頁面載入週期 內完成 pin → unpin 操作，這樣才能測試到 timeout 取消功能。

如果先 pin，然後重新載入頁面再 unpin，就測試不到這個問題，因為重新載入會重置所有狀態。

Timeout 管理機制

修復後的系統會：

  • 儲存 setTimeout 的 ID 在 this.autoShowTimeout
  • 在 unpin 時呼叫 clearTimeout() 取消排程
  • 在 recheckAutoShowConditions() 中重新評估條件

關鍵改進

相比之前的實作：

  • 即時響應：設定變更立即影響自動顯示
  • 避免競態條件：正確處理快速 pin/unpin 操作
  • 資源清理：防止記憶體洩漏和不必要的執行

技術實作細節

新增的屬性

  • this.autoShowTimeout - 儲存 setTimeout ID

新增的方法

  • recheckAutoShowConditions() - 在設定變更後重新檢查

修改的方法

  • checkAutoShow() - 加入 timeout 管理
  • togglePin() - 加入重新檢查呼叫
  • destroy() - 加入 timeout 清理

預期行為

正常流程

  1. 頁面載入，檢查自動顯示條件
  2. 如果滿足條件，排程 500ms 後自動顯示
  3. 如果用戶在 500ms 內 unpin，取消自動顯示
  4. 重新載入頁面時，由於不在白名單中，不會自動顯示

邊界情況

  • 快速 pin/unpin：正確處理連續操作
  • 已經顯示的情況：不影響已經顯示的 TOC
  • 頁面清理：destroy() 時正確清理所有 timeout
