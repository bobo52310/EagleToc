🎯 測試目標

驗證 Pin 按鈕會根據當前網域的白名單狀態顯示不同圖示：

  • 未在白名單：顯示 📌（空心釘子）
  • 已在白名單：顯示 📍（實心釘子）

🧪 測試步驟

  1. 檢查初始狀態：
    • 開啟 Smart TOC
    • 查看 Pin 按鈕圖示（應該是 📌）
    • 確認當前網域不在白名單中
  2. 測試 Pin 功能：
    • 點擊 📌 按鈕加入白名單
    • 立即觀察：按鈕圖示應該變成 📍
    • 確認看到「已將 xxx 加入白名單」通知
  3. 測試 Unpin 功能：
    • 點擊 📍 按鈕移除白名單
    • 立即觀察：按鈕圖示應該變回 📌
    • 確認看到「已從白名單移除 xxx」通知
  4. 測試持久性：
    • 重新載入頁面
    • 開啟 Smart TOC
    • 確認按鈕圖示反映正確的白名單狀態

✅ 成功標準

  • 即時視覺回饋：按鈕圖示立即反映狀態變化
  • 一致性：圖示狀態與實際白名單狀態一致
  • 持久性：重新載入後圖示狀態正確
  • 直觀性：用戶能輕易理解圖示含義

🔍 調試信息

如果圖示沒有正確切換，請檢查以下 Console 日誌：

  • 🔄 Using NEW updatePinState method v2.1 - 方法調用
  • 📍 Button set to pinned state with filled pin icon - 設為已釘選
  • 📌 Button set to unpinned state with outline pin icon - 設為未釘選
  • ✅ Is exactly in whitelist - 白名單狀態檢查

手動檢查指令：

// 檢查當前按鈕狀態 document.querySelector('.smart-toc-pin').textContent // 檢查按鈕是否有 pinned class document.querySelector('.smart-toc-pin').classList.contains('pinned') // 檢查當前域名白名單狀態 window.smartTOC.isExactlyInWhitelist(window.location.hostname) // 手動觸發狀態更新 window.smartTOC.updatePinState()

技術實作說明

🔧 修改內容

  • updatePinState() v2.1：
    • 根據白名單狀態動態設置按鈕文字（圖示）
    • 未在白名單：pinBtn.textContent = '📌'
    • 已在白名單：pinBtn.textContent = '📍'
  • 保持現有樣式：
    • 仍然使用 .pinned class 改變背景色
    • 圖示變化提供額外的視覺線索

📋 圖示選擇理由

  • 📌 (pushpin)：空心設計，表示「可以釘選」的狀態
  • 📍 (round pushpin)：實心設計，表示「已經釘選」的狀態
  • 兩個圖示在視覺上相關但有明顯區別
  • 符合用戶對「釘選」功能的直觀理解

預期行為

🎯 圖示狀態流程

  1. 頁面載入：檢查白名單狀態，設定對應圖示
  2. 點擊 Pin：更新白名單，立即切換圖示
  3. 保存設定：確保狀態持久化
  4. 頁面重載：從儲存的設定恢復正確圖示

🔄 狀態同步

圖示變化與以下元素保持同步：

  • 按鈕的 .pinned CSS 類別
  • 按鈕的 tooltip 文字
  • 內部白名單狀態 (isExactlyInWhitelist())
  • Chrome storage 中的設定
